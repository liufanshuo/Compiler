# AST->LLVM->RISCV 优化日记

## 2026-05-28 16:19 CST

### 首次记录：恢复正确性的基础优化

本次目标是将目标代码生成路径稳定为 `AST -> LLVM 风格内部 IR -> RISC-V`，并排除原先 `AST -> RISC-V` 直出后端对当前结果的影响。旧的 AST 直出 RISC-V 代码已经删除，默认汇编生成路径现在只经过 `ast_to_ir()` 和 `emit_riscv_from_ir()`。

决赛性能用例出现大面积 WA，其中大量实际输出哈希为 `68b329da9893e34099c7d8ad5cb9c940`，说明程序运行结果高度异常。排查后确认一个通用语义错误：LLVM IR 生成阶段存在“数组填充 while 循环”快捷优化，会把特定嵌套循环替换成线性填充，但没有维护原循环变量在循环结束后的最终值。SysY 中循环变量在 `while` 后继续使用是合法行为，该优化会把这些变量错误地保留在初始值，导致后续控制流或计算结果错误。

处理方式是删除该不安全优化，让 `mem_gen_block()` 按 AST 原始块顺序生成 LLVM 风格内部 IR，所有 `while` 循环继续走正常控制流生成。该修改不针对任何特定测试点、函数名或输入输出数据，也不调用外部编译器工具。

结果：修复后当前提交在评测中 AC。这个版本应作为 LLVM->RISC-V 路线的第一个稳定正确性基线。

后续优化原则：

- 先保持正确性基线，任何 IR 级优化都必须证明不改变可观察语义。
- 循环优化必须维护循环变量、break/continue、数组写入、函数调用副作用等状态。
- 不做测试点名、函数名、输入输出内容相关的特判。
- 不在编译器代码中调用 clang/gcc/llc/opt/as 等现有编译器或汇编工具。
